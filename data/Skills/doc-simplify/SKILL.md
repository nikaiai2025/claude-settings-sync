# 文書シンプル化スキル

AIが作成したドキュメントは、読み手の運用に不要な「書き手の思考過程」を含みがち。本スキルは過去事例から抽出した削減パターンを体系的に適用し、人間が運用に使える形に圧縮する。

## 基本原則

> **「決定／運用ルール／参照仕様／概念地図」だけを残し、決定に至る思考過程は別ファイルに逃がす。**

| 種類 | 例 | 扱い |
|---|---|---|
| 決定 | 「採用するのは X 方式」 | 残す |
| 運用ルール | 「失敗時は orchestrator が再発注」 | 残す |
| 参照仕様 | YAMLスキーマ、コマンド例、命名規約 | 残す |
| 概念地図 | 全体像の図、外部アナロジー（「Storybook相当」等） | 残す・必要なら補強 |
| 決定の正当化 | 採用理由、却下案、教訓引用 | 削除 |
| 未確定事項 | 残る論点、暫定値、TBD | 削除（別ファイルへ） |
| 構造論 | 「対称性」「3則」の力説 | 削除 |
| 重複サマリ | 決定事項サマリー表＋本文の二重記述 | 一方を削除 |
| メタ情報 | 作成日、関連文書リンク、本文書の役割 | 削除 |

## 削減対象カテゴリ（A〜F）

各セクション・段落・表・箇条書きを以下のいずれに該当するか判定する。

### A. 決定の正当化
- 決定に至った思考過程・採用理由
- 却下案・代替案・「採用しなかった案と理由」セクション
- 引用元・出典・教訓（「XXX教訓」「YYY経験則」など）
- ADR 風の「文脈／採用案／却下案／影響」構造の冗長部
- 「○○を理由に△△しない」のような正当化前置き

### B. 未確定・将来検討事項
- 「残る論点」「Open Questions」「Q1〜QN」セクション
- 暫定値（「N=3仮置き」「温度0.5」「現フェーズでは不要」など）
- 「将来検討」「TBD」「未定」（一行に圧縮するか削除）
- 現時点で運用判断に使えない情報

### C. 自己整合性のアピール（メタ構造論）
- 「対称性」「N則」「対称な位置づけ」のような構造美の力説
- 「BDDと同型」「自己評価バイアスを構造的に排除」のような小理屈
- 設計思想・採用方針の正当化記述（決定だけ残す）

### D. 細かすぎる場合分け
- severityごとの処理マトリクス
- 全ケースを網羅した条件分岐表（主経路＋例外1〜2件で十分）
- 運用後に書き足せばよい網羅的記述
- フォーマット例の細部（必須項目だけ示せばよい）

### E. 重複情報
- サマリ表と本文の二重記述（どちらか一方を残す）
- 同じ概念を別の切り口で複数回説明している箇所
- セクション冒頭の「本セクションでは X を扱う」前置き

### F. メタ情報・厳密スキーマ
- 作成日・関連文書リンク群（本文書を読むのに不要なもの）
- 「本文書の位置づけ」「本文書の役割」段落
- 厳密スキーマ列挙（`type: A | B | C | D` を `kind: A`（拡張可）に緩和）

## 保護対象（削減禁止）

- **決定事項**: 何が決まったか
- **運用ルール**: 守るべき決まり、判定ロジック、差し戻し経路
- **参照仕様**: フォーマット定義・スキーマ・コマンド例・命名規約
- **概念地図**: 粗くてよい全体像、外部アナロジー、用語の対応関係

## 補強の可能性

削減と並行して、以下が不足していれば追加を提案する：
- **概念地図**: 読み手が理解の足場として持つべき抽象モデル（三層構造、登場人物の関係図など）
- **外部アナロジー**: 「これは XXX に相当する」のような既知概念への対応付け

## 実行手順

### Step 1: 対象ファイルの読み込み
- 引数で指定されたファイルを Read
- 引数省略時は IDE で開いているファイル（システムリマインダー参照）
- ファイルが特定できなければユーザーに確認

### Step 2: 削減プランの作成
- 各セクション・段落・表・箇条書きを A〜F／保護対象 のどれに該当するか分類
- 以下の形式でユーザーに提示：

```
## 削減プラン

### A. 決定の正当化（削除候補）
- §1.3 決定事項サマリー表（理由列）
- 付録「採用しなかった案と理由」
- §2.1 内の godogen 教訓引用
（合計 N 箇所、推定削減量 約 XXX 行）

### B. 未確定・将来検討事項（削除候補）
...

### 補強提案
- §1 冒頭に「人間/オーケストレーター/ワーカー三層」の概念図を追加
```

### Step 3: カテゴリ別一括承認
- AskUserQuestion で各カテゴリの実施可否を確認
- 質問例: 「A〜F のどのカテゴリを削減しますか？（複数選択）」
- 補強提案がある場合は別質問で確認

### Step 4: 削減実施
- 承認されたカテゴリの内容を削除
- 出力先: **`<元ファイル名>_simplified.md`** を Write で新規作成
  - 例: `docs/foo.md` → `docs/foo_simplified.md`
  - 同名ファイル既存時は `_simplified_2`, `_simplified_3` ... と連番

### Step 5: 結果報告
- 削減前後の行数・概算文字数を提示
- 主要な削除箇所をカテゴリ別に列挙
- 「上書きしてよければ指示してください」と一行付け加える

## 量的目安

削減後の文書は、以下のいずれかを満たすことを目標とする：
- 元の 40〜60% のサイズ
- 各セクション 1 テーマ
- 表は 10 行以下、箇条書きは 5〜7 項目以下（user CLAUDE.md と整合）

ただしこれは目安であり、削減のために情報を欠落させることは禁止。**保護対象を削るくらいなら目安未達でよい**。

## 禁止事項

- 「決定／運用ルール／参照仕様／概念地図」を削らない
- 削減判断を AI 単独で確定しない（カテゴリ別一括承認を必ず取る）
- 元ファイルを上書きしない（明示指示時を除く）
- 削減対象の判定根拠を曖昧なまま進めない（迷ったら保護側に倒す）
