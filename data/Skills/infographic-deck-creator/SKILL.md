# Image-Native Infographic Deck 作成スキル

## 前提条件（実行環境の確認）

作業開始前に、以下を確認する。満たさない場合は作業を開始せず、不足している環境をユーザーへ報告する。

- **画像生成ツール**: インフォグラフィック画像の生成・修正には**Codex CLI**を使用する（実行方法は次節）。`codex --version` 等で利用可否を確認すること。PowerPoint図形による代替構築は禁止事項（§5・§12）に該当するため、代替としない。
- **PDFレンダリング環境**: §15の実レンダリング確認のため、PowerPoint（COM経由）またはLibreOfficeによるPPTX→PDF変換が可能であること。
- **PPTX構築**: PPTXファイルの生成・編集にはpptxスキル（python-pptx）を使用する。

## 画像生成の実行方法（Codex CLI）

画像生成スキルを持つCodexにCLIで指示を出し、インフォグラフィック画像を生成する。§13の誤り修正も、Codex CLIへの再指示（画像編集・再生成）で行う。

### CLIコマンド

```
codex exec --sandbox workspace-write --skip-git-repo-check "…指示プロンプト…" < /dev/null
```

- Bashツールで実行する（PowerShellは `<` による入力リダイレクトに非対応）
- `codex exec` はプロンプトを引数で渡しても stdin が開いたままだと `<stdin>` 読込で無限待機する → 引数渡し時は必ず `< /dev/null` を付ける（または `cat prompt.txt | codex exec …`）
- 生成画像は `~/.codex/generated_images/` に保存される（権限制約のためCodex CLIは他の場所へ保存できない）。生成後、作業フォルダへコピーして使用する

### 指示プロンプトの構成

```text
xxxの画像を作成し、保存されたフォルダパスを出力。必ず画像生成スキルを使用すること（スクリプト等による画像編集は行わない）。
詳細指示（勝手に変更しない）：xxxxxxxxxxxxxxx
生成された画像が発見できない場合の指示：
base64形式の可能性を踏まえて画像を捜索。data:image/png;base64,... 形式ではなく、セッションログjsonl の payload.result に裸の PNG base64（result: "iVBORw0K..."） として保存されていないかどうかを確認せよ。
```

### プロンプト作成の注意事項

- システム的な制約は具体的に指定する。本スキルでは特に、アスペクト比16:9、上部18%の白い安全領域（§9）、カラーパレットの色指定（§10）、画像内テキストの完全一致文字列（§13）が該当する
- テイスト面（画風・質感等）は、Codexの創造性を引き出すため具体的すぎる指定を避ける（具体的に書くことがマイナスの影響を与える）。§10・§12の方針・禁止事項の範囲で簡潔に指示する

# 指示

## 1. スライド作成方式

対象の内容（引数で指定されたファイルまたはテキスト）をスライド化してください。

本プレゼンテーションは、**Image-Native Infographic Deck**方式で作成してください。

各スライドは、発表者による口頭説明がなくても内容を理解できる、**読み物として単体で成立するスライド**としてください。

図解や短いラベルだけに依存せず、背景、要点、関係性、意味、結論が読者へ正確に伝わるように、**テキストによる丁寧なナラティブ説明**を含めてください。

---

## 2. 各スライドの構成

各スライドは、次の3要素だけで構成してください。

1. **PowerPoint上で編集可能な1行タイトル**
2. **PowerPoint上で編集可能な、Semiboldのナラティブ・リード文**
3. **本文、図解、ラベル、アイコン、補足説明を一体化した、16:9の画像ネイティブ・インフォグラフィック**

タイトルとリード文は画像内に生成せず、PowerPoint上の編集可能なテキストとして、全スライドの同一位置に配置してください。

リード文は単なる概要、キャッチコピー、補助的な短文にはせず、**リード文だけを読んでも、そのスライドで伝えたい内容、論点、意味、結論が完全に理解できる程度の、ナラティブで丁寧な説明文**としてください。

---

## 3. 読み物としての独立性とナラティブ

各スライドは、前後のスライドや発表者の補足説明を前提とせず、そのページだけを読んでも内容を理解できるようにしてください。

単語、名詞句、短い箇条書きを並べるだけの構成は避け、**文章として自然につながるナラティブな説明**を含めてください。

図解内のカードやラベルにも、情報を分類するだけではなく、その情報が持つ意味や文脈が理解できる文章を適切に配置してください。

ただし、冗長な文章を無秩序に詰め込むのではなく、見出し、本文、要点、補足、結論を視覚的に整理し、読み進める順序が自然に分かる構成としてください。

---

## 4. 文章の文体

タイトル、リード文、画像内の本文、見出し、補足説明を含む、**スライドに掲載するすべての文章**は、**です・ます調および、だ・である調を使用しない、簡潔で端正な説明調**としてください。

文末は、内容に応じて以下の形式を自然に使い分けてください。

* 名詞で結ぶ体言止め
* 動詞の連体形や終止形
* 「〜する構造」「〜という位置づけ」「〜が必要」「〜につながる可能性」などの説明的な名詞句
* 「〜により」「〜を通じて」「〜を前提に」など、後続する情報との関係が分かる接続表現
* 結論や意味を簡潔に示す述語表現

「です」「ます」「でした」「ました」「でしょう」「だ」「である」「となるのである」などの文末表現は使用しないでください。

ただし、体言止めを連続させて、単語、名詞句、短い断片文だけが並ぶ文章にはしないでください。主語と述語、理由と結論、前提と意味の関係が読者に伝わるように、文章として自然な流れを維持してください。

同じ文末形式を機械的に繰り返さず、名詞による結び、動詞による結び、因果や変化を示す表現を適切に組み合わせ、単調さを避けてください。

文章全体は、報告書、解説記事、調査資料に適した、客観的で落ち着いた文体としてください。会話的な表現、呼びかけ、感嘆表現、過度に断定的な表現は使用しないでください。

---

## 5. インフォグラフィックの表現方針

本文と挿絵を、左右または上下に分離しないでください。

本文の内容そのものを、以下のような視覚表現へ統合してください。

* 図解
* カード
* 矢印
* 比較
* 循環
* レイヤー
* グルーピング
* アイコン
* ピル型ラベル

PowerPoint図形を組み合わせて図解を構築するのではなく、画像生成ツールを使用し、本文テキストまで含んだ完成済みのインフォグラフィック画像を作成してください。

図解やアイコンは、テキストの代替となる装飾ではなく、ナラティブな説明と一体となって、情報の構造、関係性、流れ、比較、因果関係を理解しやすくするために使用してください。

* アスペクト比：16:9
* 幅：13.333インチ
* 高さ：7.5インチ
* インフォグラフィック画像：スライド全面に配置

## 7. タイトルの仕様

| 項目 | 指定 |
| ------- | ------------ |
| x | 0.46インチ |
| y | 0.10インチ |
| w | 12.42インチ |
| h | 0.48インチ |
| フォント | Yu Gothic UI |
| フォントサイズ | 28.2pt |
| 長い場合 | 27.4ptまで縮小可 |
| ウェイト | Bold |
| 文字色 | `#14243A` |
| 文字間隔 | 標準～マイナス0.4pt |
| 行数 | 1行 |
| margin | 0 |

タイトルは、そのスライドで扱うテーマや主張が具体的に分かる表現としてください。

抽象的な章題や一般的な名詞だけではなく、可能な限り、そのスライド固有の論点が伝わるタイトルとしてください。

タイトルは必ず1行に収めてください。

1行に収まらない場合は、まず文章を推敲し、必要に応じて文字間隔をマイナス0.4ptまで調整してください。それでも収まらない場合のみ、フォントサイズを27.4ptまで縮小してください。

文字間隔を狭くする場合は、日本語の可読性を損なわない範囲にとどめてください。

---

## 8. リード文の仕様

| 項目 | 指定 |
| ------- | ------------ |
| x | 0.48インチ |
| y | 0.60インチ |
| w | 12.36インチ |
| h | 0.68インチ |
| フォント | Yu Gothic UI |
| フォントサイズ | 15.8pt |
| ウェイト | Semibold |
| 強調箇所 | 必要な場合のみBold |
| 文字色 | `#40536A` |
| 行数 | 原則2行、最大2行 |
| 行間 | 1.05～1.10 |
| margin | 0 |

リード文は、**それだけを読めば、そのスライドで伝えたい内容が完全に理解できる文章**としてください。

単なる副題、短い要約、印象的なコピー、体言止めにはせず、以下の要素を可能な限り一つの自然な文章として統合してください。

* そのスライドで扱う対象
* 中心となる主張や結論
* その結論に至る理由や構造
* 読者が理解すべき意味や示唆

※ただし、根拠のない断定や推測はしないこと

リード文はナラティブで丁寧な説明とし、本文を読まなければ主張が分からないような、情報の不足した文にはしないでください。

日本語でおおむね70～105文字を目安とし、原則2行、最大2行に収めてください。

改行位置は、PowerPointのテキストボックス幅に基づく自然な自動折り返しに任せてください。1行目と2行目に異なる役割を割り当てたり、行の長さを揃えるために文章を不自然に変更したりしないでください。

リード文全体はSemiboldとし、中心的な結論や重要語句については、必要な場合のみ1～2か所をBoldにできます。ただし、リード文全体をBoldにしないでください。

フォントサイズを自動縮小して収めることは禁止します。

2行を超える場合は、フォントサイズを縮小せず、内容の重複や冗長な表現を取り除いて文章を推敲してください。

PowerPointからの実レンダリング後も、フォントサイズが15.8ptに維持されていることを確認してください。

---

## 9. 画像上部の安全領域

画像生成時は、画像上部の**18%を完全な白い安全領域**として確保してください。

この領域には、以下の要素を一切配置しないでください。

* 文字
* カード
* 線
* アイコン
* 背景色の変化
* 重要な図形
* 装飾要素

本文およびインフォグラフィックの主要要素は、必ず上部18%の境界より下から開始してください。

編集可能なリード文の下端と、画像内の本文およびインフォグラフィックの開始位置との間には、最低0.05インチの空きを確保してください。

## 10. デザイン方針

明るく洗練された、フラットな2Dインフォグラフィックとしてください。

### カラーパレット

落ち着いたニュートラルカラーを基調とし、温かみと知性を感じる配色としてください。

* 背景：
  * アイボリーホワイト
  * 淡いサンドベージュ
  * ごく薄いグレージュ
* 本文：
  * チャコールネイビー
  * ダークスレート
* カード：
  * ウォームホワイト
  * 背景との差が明確な高コントラスト構成
* アクセントカラー：
  * ディープティール：主要概念、結論
  * セージグリーン：補足、安定、継続
  * テラコッタ：課題、変化、注意事項
  * マスタードイエロー：重要ポイント、強調
  * ダスティブルー：プロセス、接続、参照情報
  * プラム：高度な概念、差別化要素

アクセントカラーは装飾として均等に配置せず、情報の意味、分類、重要度に応じて一貫して使い分けてください。

彩度は全体的に抑え、カード、矢印、ピル、アイコン、見出しの間で十分なコントラストを確保してください。

### スタイル

* 均一な線幅
* 控えめな角丸
* 控えめな影
* 明確な情報階層
* 明確な読む順序
* 高密度ながら整理された構成
* 視覚要素を情報構造や因果関係の説明に使用する
* ナラティブな文章を無理なく読み進められるレイアウト
* 見出し、本文、要点、補足、結論の役割が判別できる文字設計

ビジュアルは装飾目的ではなく、情報の構造、比較、関係性、流れ、因果関係を説明するために使用してください。

## 11. 情報密度

情報量は多く、スライドがビジーになっても構いません。

余白を増やしてミニマルにするのではなく、以下の要素を用いて高密度な情報を整理してください。

* カード
* 見出し
* ピル
* 色
* アイコン
* 矢印
* グルーピング
* 階層構造
* 比較表現
* プロセス表現
* 丁寧なナラティブ文章表現

情報量を減らすために説明文を省略するのではなく、文章を適切な単位に分割し、カード、見出し、強調、接続線などを使用して、読み物として理解しやすい情報構造へ整理してください。

短いキーワードだけで情報量を表現するのではなく、必要な文脈、理由、意味、結論を文章として記載してください。

## 12. 禁止事項

以下の表現は使用しないでください。

* 写実表現
* ストックフォト
* 3D表現
* ベベル
* ガラス表現
* 重い影
* チープに見えるPowerPoint図形
* 本文と挿絵を分離したレイアウト
* 小さすぎる文字
* 低コントラスト
* ページ番号
* 透かし
* 偽のロゴ
* 画像内でのタイトルの重複
* 画像内でのリード文の重複
* 単語や短いラベルだけで説明を完結させる構成
* 発表者の口頭説明がなければ理解できない情報の省略
* 文脈や結論を欠いた箇条書きの羅列
* 内容を説明しない抽象的なキャッチコピー

## 13. 画像内テキストの正確性

画像内に表示する日本語は、すべて**完全一致の文字列**として画像生成プロンプトへ指定してください。

生成後は原寸で、以下を確認してください。

* 誤字
* 欠字
* 文字化け
* 製品名
* 英語のスペル
* 数値
* ラベル
* 矢印の接続関係
* 図解内の論理関係
* 情報間の矛盾
* 因果関係の不整合
* 文章の主語と述語の対応
* ナラティブ文章の自然さ
* 説明に必要な文脈の欠落
* リード文と本文の主張の整合性

誤りがある場合は、PowerPointテキストを重ねて隠すのではなく、画像編集によって修正してください。

## 14. 情報源と表現上の制約

製品情報や時点依存の情報は、公式一次情報を用いて確認してください。

以下の表現は避けてください。

* 過度なセールス表現
* 製品保証と受け取られる断定
* 根拠のない優位性の主張
* 装飾的で内容を増やさない文章
* 公式情報から確認できない推測
* 根拠や理由を示さない結論
* 読者の理解に必要な前提を省略した説明

ナラティブな説明を追加する場合も、公式情報から確認できる事実と、そこから直接導ける説明の範囲にとどめてください。

## 15. レンダリングと品質確認

完成後は、必ずPowerPointからPDFへ実レンダリングしてください。

以下の2つの表示方法で確認してください。

1. 全スライドの一覧表示
2. 各ページの原寸表示

少なくとも1回、render → fix → re-renderの工程を実施してください。

確認対象には、以下を含めてください。

* タイトルとリード文の位置
* フォント
* フォントサイズ
* ウェイト
* タイトルの文字間隔
* 改行
* 画像の配置
* 上部18%の安全領域
* 文字の可読性
* 画像内テキストの正確性
* 情報階層
* スライド間のデザイン統一
* PDF変換時のレイアウト崩れ
* 各スライドが単体の読み物として成立しているか
* 発表者の説明がなくても内容を理解できるか
* リード文だけでスライドの主張と結論が伝わるか
* 本文に背景、関係性、理由、意味、結論が含まれているか
* ナラティブ文章が不自然に途切れていないか
* 図解と文章が同じ論理構造を示しているか
* タイトルが1行に収まっているか
* タイトルの文字間隔がマイナス0.4ptを下回っていないか
* リード文が不必要に1行へ短縮されていないか
* リード文が原則2行、最大2行に収まっているか
* リード文に70～105文字程度の情報量があるか
* リード文の実フォントサイズが15.8ptに維持されているか
* リード文の基本ウェイトがSemiboldになっているか
* リード文全体がBoldになっていないか
* リード文の重要箇所以外が過剰に強調されていないか
* リード文が自然な自動折り返しになっているか
* 行の長さを揃えるために文章が不自然に変更されていないか
* リード文と画像本文の間に最低0.05インチの空きがあるか
